# 场景调研：中国移动网络下的 TCP 拥塞控制选型

本文档记录四个目标场景的调研结论，作为 NetBoost 算法选型的依据。

## 1. 高铁 / 地铁（train）

### 网络特征

- 列车高速移动导致高频基站切换。实测数据：高铁 30km 内可穿越 23 个基站，切换时 RTT 毫秒级跃变（可超 300ms），带宽在 800ms 内可从 100Mbps 骤降至 2Mbps。
- 切换瞬间吞吐量骤降甚至归零，是蜂窝网络切换对 TCP 最致命的影响。
- 切换过程伴随数据包丢失，传统丢包驱动算法会误判为拥塞，触发窗口减半。

### 算法适配

BBRv3 基于带宽/RTT 建模，不依赖丢包信号。切换后能快速重新探测瓶颈带宽并恢复吞吐，相比 CUBIC（切换丢包触发窗口减半）恢复更快。这是高铁场景的核心优势。

## 2. 演唱会 / 高密度人群（crowd）

### 网络特征

- 数万人聚集导致基站过载：单小区用户数暴增数十倍，空口资源被挤爆，回传链路拥塞。
- 实测：大型活动期间上行流量增 4-8 倍，下行流量和用户数增 3 倍。
- 这是**纯物理瓶颈**——基站能同时承载的用户数有限，每个人分到的带宽被压缩到几乎不可用。

### 算法适配

CUBIC。在严重拥塞下，CUBIC 的丢包驱动+公平性设计不会激进抢占带宽，避免加剧他人拥塞。BBR 系在过度拥塞下可能因激进探测加剧不公平，且其 pacing 机制在移动设备多连接场景下吞吐可能反而低于 CUBIC。

## 3. 卫生间 / 弱信号（weak）

### 网络特征

- 信号弱导致高随机丢包（非拥塞丢包）、低带宽、RTT 抖动。
- 传统丢包驱动算法（CUBIC/Reno）会把随机丢包误判为拥塞，盲目减半窗口，导致吞吐极低。

### 算法适配

Westwood。专为无线随机丢包设计，通过 ACK 到达速率估计可用带宽，丢包时按带宽估计恢复窗口而非盲目减半。在弱信号高丢包下吞吐显著优于丢包驱动算法。

## 4. 家用 WiFi（wifi）

### 网络特征

- bufferbloat（缓冲膨胀）：路由器缓存过大导致排队延迟飙升。
- 多设备竞争、延迟抖动。Wi-Fi 弱网体现在 RTT 抖动和高丢包率，接入终端越多越弱。
- 2.4GHz 穿墙强但慢，5GHz 快但穿墙差，隔墙场景（如卫生间）信号弱。

### 算法适配

BBRv3 + fq。BBR 系低排队延迟特性配合 fq qdisc 的 pacing 机制，能有效降低 bufferbloat 延迟。fq 为每条流维护独立队列，多设备下公平性更好。

## 5. 算法对比总结

| 算法 | 原理 | 优势 | 劣势 | 适用 |
|---|---|---|---|---|
| CUBIC | 丢包驱动，立方函数 | 公平性好、实现简单 | 随机丢包误判、恢复慢 | 高带宽、拥塞 |
| BBRv1 | 带宽/RTT 建模 | 高吞吐、低延迟 | 高丢包下激进、公平性弱 | 高带宽低丢包 |
| BBRv3 | BBRv1+v2 改进 | 弱网恢复快、更稳定 | 跨境高丢包下利用率低 | 移动网络、切换频繁 |
| Westwood | ACK 速率估计带宽 | 无线随机丢包友好 | 公平性一般 | 弱信号、无线 |
